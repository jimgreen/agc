# AGC controller

独立的自动发电控制（AGC）程序，支持交流侧、直流侧及交直流混合场景中的风电、光伏、储能、燃料电池、制氢负荷和柴发协同控制。

## 控制策略

- 决策只使用实时采集量，不依赖 p_fur 预测值。
- 新能源优先：先计算新能源接纳空间（含储能 SOC 约束），再进行小步试探调节。
- SCADA 入口实测平衡。新能源上涨是未确认的试探指令，不能作为柴发或构网储能降功率的依据；平衡电源被动承担功率变化，后续由遥测观察。
- 代码保留传统缺额/盈余调节辅助函数，默认实测平衡策略不调用这些主动平衡分支。
- 受控设备支持 p_step/p_dead（以及兼容别名）控制步长和死区，减少频繁调节。

## 文件

- agc_ctrl.py：AGC 控制器及命令行入口。
- efile_read.py：E-file 读取和写回支持。
- paths.py：独立仓库路径解析。
- model_real.e：可直接运行的 AC/DC 混合示例模型。

## 运行

在本目录执行：

    python agc_ctrl.py --help
    python agc_ctrl.py --model model_real.e --step

控制器默认从模型文件所在目录读取模型；可通过 --model 指定其他 E-file。运行前请确保实时测量源可用；model_real.e 仅用于接口和策略验证。

## Web 人机界面

在本目录执行：

    python web/server.py

浏览器打开 `http://127.0.0.1:8765/`。Web HMI 提供系统总览、实时监视、参数配置、日志查询和历史查询，并支持启动/停止、开环/闭环切换。

实时监视页面可逐台设置“远方 · 自动”或“本地 · 曲线”。远方设备参与闭环自动决策；本地设备跳过自动决策，使用保存的默认功率曲线。每台设备的默认曲线为 96 点，按 15 分钟覆盖 00:00—23:45，可在“96点曲线”编辑器中保存。

实时监视中的“设备控制详情”可选择任意设备，修改受控状态、运行状态、控制步长、控制死区、功率上下限和默认功率；右侧可编辑 96 点曲线。详情面板同时显示该设备的实时功率曲线、AGC 指令曲线、默认曲线，以及每个控制时刻的实时值、指令值、默认值和参数。

实时监视已按“实时总览、设备列表、设备详情、控制指令”拆分为分页标签；设备、日志、历史和控制指令表均采用分页显示，页面保持在当前视口内，不产生横向或纵向滚动条。

Web 配置、曲线和历史数据保存在下述 SQLite 数据库，`web/data/` 仅用于日志、控制输出和旧 JSON 配置迁移，不修改原始 `model_real.e`。Web 在检测到新周期后同步计算后台写入的设备采样、指令和环境量；历史周期中的模式与受控状态不覆盖当前配置。

实时轮询使用 `/api/state?lite=1&history_since=<上次周期>`，首次及出现新周期时返回最近 240 个周期的历史，省略 96 点曲线。设备详情按需读取，后台标签页暂停轮询。设备列表可搜索、勾选和批量切换本地/远方，接口逐台返回结果。遥调 YT 仅在同一采集周期内去重，失败或进入新周期会清除缓存；遥控 YK 每次显式操作均独立下发。接口接受指令不等于现场已执行。

设备列表支持按名称或 ID 快速检索；默认功率、曲线功率必须处于设备上下限内，运行状态只接受 0/1。SCADA 采集失败仍会逐周期更新状态计数，但相同点位的重复日志按时间限频，避免通信故障时拖慢计算和 SQLite 写入。

## AGC SQLite 数据库

Web 服务和 AGC 计算后台共用 `D:\\codex\\sqldb\\realtime\\agc\\agc.db` 作为运行数据库，建表脚本为 `web/agc_schema.sql`。也可以通过 `AGC_DB` 环境变量覆盖数据库文件路径。计算后台启动时读取数据库中的系统配置、设备受控状态、控制参数和 96 点默认曲线；每个控制周期完成后写入系统周期、设备实时采样和 AGC 指令，供 Web 界面实时展示、日志查询和历史查询。

- `system_settings`：控制周期、步长和开环/闭环模式
- `devices`：设备受控状态、运行状态、功率上下限、步长、死区和默认功率
- `device_curves`：每台设备 96 个 15 分钟默认曲线点
- `control_cycles`：各控制周期的系统功率、环境量和 AGC 平衡
- `device_samples`：各设备在每个控制时刻的实时功率与指令功率
- `event_logs`：控制启动、模式切换、设备指令和运行日志

服务首次启动时会把旧版 `web/data/settings.json`、`device_modes.json`、`history.json` 和 `command_history.json` 自动迁移到 SQLite；之后界面查询直接读取数据库。SQLite 文件及运行时数据库文件已加入 Git 忽略规则。

AGC Web 和计算后台打开数据库时，会从实际 SQLite 表同步 RTDB 内置结构，已有数据库原地补齐定义。RTDB 使用原生 SQLite 只读模式浏览原表，需要支持该模式的 RTDB 版本。新增表须声明主键，修改已有表时使用明确的迁移 SQL，通过 `agc_schema.apply_schema(connection, database_name, script)` 提交物理表和结构定义。迁移脚本不要自行开始或提交事务。

## SCADA 四遥联动

计算周期先通过 SCADA 遥测（YC）和遥信（YX）刷新模型；YX 可通过设备的
`run_yx_id`/`status_yx_id`/`yx_id` 映射同步设备运行状态。闭环模式下，自动决策和
本地默认曲线才会通过遥调（YT）下发有功指令；设备运行状态的界面操作通过遥控（YK）
下发。开环模式仍采集 YC/YX，但不会发送自动 YK/YT 指令。指令接口返回失败或超时
时，内存中的控制值回滚，失败原因写入日志和 `command_results`，下一周期可重试。

现场可以任选一种适配方式：

- Python FES 模块：设置 `AGC_FES_MODULE`（默认 `fes_interface`），提供
  `get_yc_value`、`get_yx_value`、`send_yk_value`、`send_yt_value`；兼容 4/5 参数
 旧接口以及 2/3 参数简化接口。
- HTTP：设置 `AGC_SCADA_API_URL`，读取使用
  `/api/points/yc|yx?rtu_id=&pnt_no=&limit=1`，写入默认使用
  `/api/points/{kind}/{rtu}/{pnt}`。若现场命令路由不同，可用
  `AGC_SCADA_COMMAND_URL` 覆盖，其中支持 `{kind}`、`{rtu}`、`{pnt}` 占位符；
  `AGC_SCADA_TOKEN` 和 `AGC_SCADA_TIMEOUT` 分别配置认证和超时。
- `scdfe_c` 指令服务：设置 `AGC_SCADA_COMMAND_ENDPOINT` 指向认证端点 JSON；若
  设置 `AGC_SCADA_DB`，程序也会自动查找同名 `.scdfe_command.json` 端点文件。

设备到现场控制点的映射写在模型设备行的元数据中：有功遥调支持
`p_yt_id`/`yt_id`/`control_yt_id`/`power_yt_id`，或 `p_yt_rtu`+`p_yt_pnt`；启停
遥控支持 `run_yk_id`/`status_yk_id`/`yk_id`/`control_yk_id`，或
`run_yk_rtu`+`run_yk_pnt`。没有映射的设备仍可运行仿真和界面逻辑，但不会伪造现场
指令成功；接入真实设备前必须按现场点表补齐映射并验证权限。

## 操作与效率改进（2026-11-18）

- 设备详情按实时曲线、控制参数、控制时刻指令分标签。未保存编辑保留在本次页面会话中，支持撤销，保存仅提交改动字段；修改步长不会抹平已保存的 96 点曲线。
- 曲线支持全天填充、本组 24 点线性生成、翻页保留输入和恢复已保存值。储能曲线可为负值；功率边界由模型的充放电额定值确定。实际执行受启停、SOC、步长、死区约束，预设值与受限指令分别记录。
- 主页面、历史查询、系统参数和仿真输入拆分标签；表格按可用高度分页。修复高 DPI 屏幕上画布高度随刷新增长的问题。
- 多参数先完整校验，再在同一 SQLite 事务保存；仅更新目标设备，曲线未变化时不重写 96 行。系统周期与设备采样一起提交，两个写入进程不再覆盖同一个周期号。
- 同周期快照复用已加载历史，最新设备采样按设备/周期索引查询。指令记录设备分类从重复扫描改为直接映射；SCADA 函数签名适配使用有界缓存，指令审计保留最近 1000 条。
- Web 使用排他监听，端口绑定成功后才创建运行状态；`/api/health` 返回 PID 和启动时间，便于确认重启后的唯一实例。

## 操作与展示增强（2026-11-18 第二轮）

- “实时监视”新增“运行分析”标签：展示实测负荷、新能源、储能吸收余量和新能源新增接纳空间，并逐台说明停运、本地曲线、被动平衡、功率上限、死区或可试探原因。该页面只读，不下发指令；新能源上涨仍是未确认试探，不能据此降低柴发或构网储能功率。
- “历史查询”支持开始时间（含）、结束时间（不含）、按周期游标分页、较新/更早一批、范围统计和 JSON 导出。查询锚定首次最新周期，后台新增周期不会改变正在翻阅的历史窗口。
- 96 点曲线编辑器增加“全天预览”和“导入导出”标签。预览显示最小/最大功率和正负向电量；导出格式为 `agc-curve/1`，导入后只进入编辑区，经过范围校验并点击保存才写入数据库。
- `/api/analysis` 为只读运行解释接口；`/api/history-query` 支持 `start`、`end`、`anchor`、`before`、`limit`，返回统计、游标和是否还有更早数据。
- 默认控制路径复用已读取的步长值，跳过本地新能源设备的自动试探；1000 个相同模型场景的决策输出与基线 `c8f32ce` 完全一致，11 轮配对中位耗时下降约 8.68%。

## 多页面 Web HMI（2026-11-18）

Web HMI 已拆分为独立 HTML 页面，根路径 `/` 只负责跳转到 `/overview.html`：

- `/overview.html`：系统总览
- `/monitor.html`：实时监视（设备列表、设备详情、控制指令和运行分析标签）
- `/config.html`：参数配置
- `/logs.html`：日志查询
- `/history.html`：历史查询

每个页面只加载自己的功能区，共享导航、控制栏和接口脚本；页面之间通过导航跳转，不再把所有主功能视图堆在同一个 HTML 文档中。页面级联动检查脚本为 `output/playwright/multipage_check.py` 和 `output/playwright/multipage_console_check.py`。

页面采用紧凑布局：删除说明段落、辅助提示和冗余小字，压缩标题、卡片、查询区和表格行高，把可用空间优先分配给实时曲线、历史曲线、设备表和控制指令表。
